# Лабораторная 6: Alamofire, GET/POST и обработка ошибок

Итоговое приложение StudyNotes: Swift, iOS 17+, SwiftUI, MVVM, Repository, Dependency Injection, SwiftData + UserDefaults, XCTest, Swift Concurrency, Alamofire. Минимум четыре экрана выполнен: список заметок, детали, редактор, настройки; дополнительно есть анализ, лента и детали публикации.

GET /posts декодирует JSON в [RemotePost], исключает пустые заголовки и сортирует по id. POST /posts кодирует NewPost в JSON и декодирует ответ с id. Сеть вынесена в AlamofireTransport, HTTP/JSON-разбор — ResponseParser, прикладная логика — APIClient, UI-состояние — PostsViewModel. Протокол HTTPTransport позволяет проверять запросы без интернета.

Проверяются отдельно transport error, наличие HTTP-ответа, диапазон 200…299, пустая data, некорректный JSON. Ошибки выводятся на экран, GET можно повторить; есть индикаторы и защита от повторной отправки. Alamofire выполняет сетевую работу/сериализацию вне главного актора; UI обновляется через @MainActor после await.

Важно: JSONPlaceholder — учебный сервер. POST возвращает объект (обычно id 101), но не сохраняет его на сервере. Интерфейс сообщает об этом. Долговременный CRUD демонстрируется локальными заметками в SwiftData.

На защите: продемонстрируй CRUD заметок и сохранение настроек; «Анализ» — два фоновых вычисления; «Лента» — GET, детали публикации, POST с собственным текстом. Для сетевой ошибки отключи соединение на реальном/удалённом Mac; для HTTP 404, пустого тела и ошибочного JSON покажи детерминированные XCTest. Appetize использует сеть облачного устройства — отключение Wi-Fi на Windows лишь разорвёт трансляцию. Тесты не зависят от доступности внешнего API.

## Запуск и проверка

На Mac: `brew install xcodegen`, затем из этой папки `xcodegen generate`, открой `StudyNotes.xcodeproj`, выбери iPhone Simulator и нажми Run. Test: Product → Test (Cmd+U). Для физического iPhone включи подпись и выбери свой Team: в учебной конфигурации CODE_SIGNING_ALLOWED=NO для облачного симулятора.

На Windows смотри инструкцию [WINDOWS.md](WINDOWS.md). Автоматическая проверка — workflow **Lab 6** в Actions форка. Workflow собирает код и запускает XCTest; статус нужно смотреть в конкретном запуске. Наличие тестов в PR само по себе не означает, что они прошли.

Каждая лабораторная самостоятельна: checkout ветки `codex/lab-6` содержит весь нужный для неё код, другие лабораторные не требуются. Лабораторные 7–8 не изменены: их задания не предоставлены.
