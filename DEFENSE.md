## Что объяснить своими словами

**Зачем MVVM?** View отображает состояние и передаёт действия. ViewModel валидирует ввод, вызывает зависимости и публикует результат. Модель Note описывает данные. База и HTTP не находятся во View.

**Какие паттерны?** MVVM, Repository (абстракция доступа к заметкам), Dependency Injection (зависимости передаются в init), Adapter (SwiftData-объект превращается в Note). Тесты используют MemoryNoteRepository, FailingRepository и StubTransport.

**Зачем два хранилища?** SwiftData подходит для структурированных записей с идентификаторами и датами, CRUD и сохранения между запусками. UserDefaults подходит для небольших настроек; здесь это флаг сортировки. Крупные массивы заметок в UserDefaults не складываются.

**Где CRUD?** `SwiftDataNoteRepository.save` создаёт запись или обновляет по UUID, `fetch` читает, `delete` удаляет. ViewModel вызывает эти операции, обрабатывает ошибку и обновляет UI. При ошибке сохранения ModelContext откатывается.

**Где два использования многопоточности?** `AnalysisViewModel.search` и `.calculate`. Task.detached получает immutable Sendable-снимок заметок и выполняет вычисления вне MainActor. После await код ViewModel продолжает работу на MainActor и присваивает @Published. Изменение запроса отменяет старую операцию через `.task(id:)`, cancellation handler и Task.checkCancellation. async — это возможность приостановки; оно само по себе не означает фоновый поток. Актор не закреплён за отдельным фоновым OS-потоком.

**Почему не отправляем ModelContext в detached?** Он имеет собственные ограничения изоляции. Передаются value-модели Note; для вычислений не нужен доступ к базе.

**Как устроена сеть?** View → PostsViewModel → PostsService/APIClient → HTTPTransport/AlamofireTransport → API. Данные приходят как Data + HTTP status, затем ResponseParser проверяет статус и JSONDecoder декодирует DTO. GET фильтруется и сортируется. POST использует JSONEncoder и Content-Type application/json.

**Какие ошибки различаются?** Отсутствие соединения/таймаут, отсутствие HTTP-ответа, HTTP вне 200…299, пустые данные и некорректный JSON. HTTP-ошибка может иметь корректное тело, поэтому HTTP-код проверяется до декодирования успешного объекта. CancellationError не показывается как ошибка пользователю.

**Почему POST не виден в следующем GET?** JSONPlaceholder имитирует создание, возвращает объект, но не сохраняет его. Это учебное API. Постоянный CRUD реализован локально через SwiftData.

**Что тестируется?** Lab1 полностью охватывает требования примера, пустые входы, геометрию, границы, некорректные размеры, min/max-кучу, дубликаты, пользовательские элементы и 1000 вставок. В приложении проверяются валидация, CRUD, ошибки хранилища, настройки, поиск, статистика, отмена, HTTP-коды, JSON, GET/POST и состояние ViewModel. UI-тест Lab6 проходит CRUD, перезапуск, сохранение настройки и навигацию. Внешний сервер не используется в unit-тестах.

**Чем unit-тест отличается от UI-теста?** Unit-тест проверяет отдельную логику с управляемыми зависимостями, быстро и детерминированно. UI-тест запускает приложение и взаимодействует через доступные пользователю элементы, проверяя связь экранов и компонентов.

## Лабораторная 7: три unit-теста и два UI-теста

Самостоятельный проект: Lab7/project.yml. Два target: StudyNotesTests и StudyNotesUITests, оба входят в схему StudyNotes.

Unit-тесты находятся в Lab7/Tests/NotesViewModelTests.swift: успешный CRUD, валидация названия и ошибки репозитория с восстановлением. Это три метода test…, каждый использует Arrange → Act → Assert и проверяет поведение NotesViewModel. В зависимости передаются MemoryNoteRepository и FaultInjectingRepository. Интернет и диск не используются.

UI-тесты находятся в Lab7/UITests/StudyNotesUITests.swift: первый проверяет создание/редактирование/удаление заметки и сохранение текста после перезапуска, второй — сохранение настройки сортировки. Они запускают настоящее приложение, работают с SwiftData/UserDefaults и сохраняют PNG. Уникальный заголовок заметки и возврат исходной настройки позволяют запускать тесты независимо. Наличие элемента ожидается через waitForExistence, изменение значения — через XCTest expectation, без произвольных sleep.

На защите покажи два test target, пять методов тестов, подмену репозитория, проверки XCTAssert…, затем успешный workflow Lab 7 со строками Executed 3 tests / Executed 2 tests. Appetize для просмотра логов, покрытия и PNG на Windows не требуется.
