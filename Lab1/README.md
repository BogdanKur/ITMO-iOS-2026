# Лабораторная 1: Swift: коллекции, геометрия и очередь с приоритетом

Все шесть операций над заказами реализованы в `OrderAnalytics`. Результаты примера: оплаченные суммы `[1200, 5400, 300]`, неоплаченная сумма `2900`, клиенты `Анна, Иван, Олег`, промокоды `SALE10, NEW, SALE10`, лучший клиент `Анна` с суммой `6600`.

`Point` — value type с синтезированными Equatable/Hashable и расстоянием через hypot. `Rectangle` отдельно заменяет каждую некорректную сторону на 1; границы входят в contains. scale меняет размеры, сохраняя origin; нулевой, отрицательный, бесконечный фактор и переполнение игнорируются.

`PriorityQueue<Element>` — собственная двоичная куча на массиве. enqueue/dequeue: O(log n), peek: O(1), память: O(n). Компаратор `>` создаёт max-heap, `<` — min-heap. При равном приоритете FIFO не обещается.

На защите: `swift run Lab1Demo`, затем `swift test`. Объясни filter/map, reduce с аккумулятором, compactMap, Set и Dictionary(grouping:by:), индексы родителя `(i-1)/2` и детей `2*i+1`, `2*i+2`. Покажи пустую очередь, дубликаты и пользовательский тип в тестах.

## Запуск и проверка

Из папки Lab1: `swift run Lab1Demo` и `swift test`. Swift доступен для Windows, но требуется установленный toolchain и его зависимости: https://www.swift.org/install/windows/ . Готовый вывод и лог тестов также публикует workflow Lab 1.

На Windows смотри инструкцию [WINDOWS.md](WINDOWS.md). Автоматическая проверка — workflow **Lab 1** в Actions форка. Workflow собирает код и запускает XCTest; статус нужно смотреть в конкретном запуске. Наличие тестов в PR само по себе не означает, что они прошли.

Каждая лабораторная самостоятельна: checkout ветки `lab-1` содержит весь нужный для неё код, другие лабораторные не требуются. Лабораторные 7–8 не изменены: их задания не предоставлены.
